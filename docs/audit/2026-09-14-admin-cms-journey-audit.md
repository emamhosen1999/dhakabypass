# Admin CMS journey audit — Dhaka Bypass Expressway

**Date:** 14 September 2026 · **Scope:** every screen under `app/admin/(dash)/**`, `app/admin/login`, their server actions and the `lib/` functions they call · **Mode:** audit only; no source file changed.

**Method.** Every screen, action file and supporting component was read (citations are `file:line` in the working tree on branch `chore/2026-09-06-cutover-and-audit` at 14 Sep 2026 ~11:00 +06, which includes another engineer's uncommitted alerts/cameras work). Six behaviours were then confirmed in the local production (standalone) build already serving on `127.0.0.1:3001`, signed in as throwaway `admin` and `translator` users inserted into the local `dhakabypass` database and deleted afterwards; every destructive button was clicked with `window.confirm` stubbed to *cancel*, and the local data was checked unchanged afterwards (home page, 58 pages, 35 media rows, settings timestamps). Nothing ran against production.

Marked **[verified]** = observed in the browser. Everything else is read from code; where a claim depends on React/Next runtime behaviour that was not clicked through, it says so.

**Overall score: 37 / 100.** The infrastructure pieces that exist (runAction notices, AdminFormGuard, block revisions, draft preview, drag reorder, the alignment acceptance tests, the users lockout rules) are individually good. What stops the admin reaching "full CMS" is structural: one row per block/locale serves as both draft and live copy, a page itself cannot be renamed, re-addressed, published or unpublished, nothing outside block text has history, every delete is a hard delete, a refused save throws away what the operator typed, and two screens of personal data are open to every role.

## 5. Prioritised implementation plan to reach 100/100

Ordered by risk to the public site and to data, grouping fixes that share infrastructure. Each step names the pieces it closes.

1. **Close the privacy and front-door holes (same day).** Role gates on `requests/page.jsx` and `messages/page.jsx`, with the dashboard counters hidden for non-admins (R1, R2). Filter `NAV` by capability (R3). Refuse delete of `home`/`not-found` in `deletePageAction` and hide the button (X1). Refuse interchange delete while `toll_od_rates` reference it, and add a migration changing `fk_toll_od_origin/destination` to `ON DELETE RESTRICT` (U1, X5). Fix the `pageSlugsUsingMedia` call (F9).

2. **Separate draft from live (`draft_data`).** Migration adding `draft_data JSON NULL, draft_updated_at, draft_updated_by` to `block_translations` and `news_translations`, plus `blocks.status` honoured by the public reader for new blocks. `saveBlockTranslation` writes the draft; a new `publishBlockTranslation` promotes it and records a revision. The preview reads the draft. Badges for "Unpublished changes" and "Discard draft". New blocks start as draft (D1, D2, C5, confirmation rows 3 and 22).

3. **Page settings panel.** On the block editor: per-locale title, SEO title/description with counters, sharing image (ImageField), address with automatic 301 on change, parent, and status Draft/Published/Scheduled (`publish_at`, `unpublish_at`, checked by the public reader). Show "last published by/at". Correct the Settings and Search banners (D3, D4, D5, M3, V6, X2 partially).

4. **One record-revision + audit writer inside `runAction`.** Change the signature to `runAction(fn, { action, entity: {type, id}, snapshot: async (q) => row })`. Before the body runs it snapshots the target into `revisions` (generalising `recordRevision`), and after success it writes `audit_log` (actor, action, target, redacted form detail). A shared `<RecordHistory entityType entityId>` server component (diff + Restore with `data-confirm`) goes into every corridor record form, menus, wording, settings sections, route meta, redirects, media, news and cameras. A `/admin/activity` screen for admins. This covers H1, H2, H3, H4, R7, D5, and makes C4/C6 recoverable.

5. **Trash / soft delete.** `deleted_at`/`deleted_by` on pages, blocks, news_updates, media (files moved to `.trash/` for 30 days), menu_items, redirects, route_meta, segments, interchanges (with their fares), toll_rates, toll_od_rates, advisories, cameras and service_requests (archive). Readers get a `notDeleted()` helper. An "Deleted. Undo" toast via the flash cookie carrying the entity. `/admin/trash` with Restore and admin-only "Delete forever", plus a nightly purge job (U2–U7, H7).

6. **Confirmation 2.0 in AdminFormGuard.** Every destructive or live-affecting form gets a server-built `data-confirm` naming the record and its blast radius: page (blocks, menu links pointing at it), menu heading (child count), media (usages from an extended `mediaUsages` covering news, settings, route meta and cameras), interchange (fares), user role and password, robots block_all, provisional flag, alert recipients and cost. Add a `data-noconfirm` opt-out and per-button `data-pending`/`data-flash`. Warn in development about unlabelled destructive buttons. Server-side tick-box for site-wide switches (C1–C13, M1, X2–X4).

7. **Keep the operator's input and state.** A shared `<AdminForm id>` wrapper that (a) keys itself on the saved record, (b) on a `?notice=` failure restores the values stashed in sessionStorage at submit (passwords and files excluded), (c) clears `notice` from the URL on success, and (d) moves focus to the notice or back to the record anchor. Convert TrafficForm to return `values`. Add the resync pattern to ImageField/RichTextField (F1–F5, A3).

8. **Dirty-form guard and optimistic locking.** AdminFormGuard marks forms dirty on input, warns on `beforeunload` and on in-admin navigation (including language tabs), and shows "3 blocks have unsaved changes". Record forms carry `updated_at`; repositories update `WHERE id=? AND updated_at=?`, and on conflict return a notice naming who changed it, with step 7 preserving the operator's text (N1, N2).

9. **`<AdminList>` component.** Search (`?q=`), filters, sort, pagination and an empty state for Pages (tree), Media (grid, "no description"/"in use" filters), News, Messages, Requests (tracking number/phone search), Sign-ups (CSV export, logged), Redirects, Alerts subscribers and the Toll fare matrix (origin × destination grid per class/direction with a single edit panel). Menus gain edit-in-place and drag reorder using the existing BlockSortableList pattern (S1–S5, T4, A5).

10. **Guidance and translation workflow.** Registry fields gain `hint`, `maxLength`, `placeholder` and `required` markers, with inline field errors. English source rendered beside each block field for translators. A translation-status screen across blocks, news, menus, corridor records, media alt text and ui strings. Language-tab progress badges. bn/zh labels for segments, with merge-not-replace. Label maps for enums, vehicle class as a select, chainage in `K3+900` everywhere, ImageField pickers for settings image paths, redirect loop detection, menu href validation (V1–V9, T1–T5, M2, M4).

11. **Role-aware UI and a coherent admin design language.** Hide controls a role cannot use (block structure for translators, news editor for translators). Replace the error-boundary heading for permission refusals. Shared `AdminPage`/`AdminButton`/`AdminField` in `app/admin/admin.css` replacing the three current button dialects. Visible words on icon-only destructive buttons. Unique ids on the news translation forms (R4–R6, F6, F7, A1, A2, A4, V9).

12. **Operational history for requests, traffic and alignment.** `service_request_events` timeline with an append-only note. A measurement log for section traffic. The last N alignment imports with "Put back the previous alignment". `sent_by` on alert broadcasts, a test-send to the operator's own number, and a segment counter (H5, H6, C10).

Completing steps 1–3 removes every blocker. Steps 4–8 lift standards H, U, N and F from under 1 to roughly 8. Steps 9–12 cover findability, guidance, translation, roles and consistency, which is what remains between that and 100.
